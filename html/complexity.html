Four Common Complexity Antipatterns & Senior Fixes

Frequent algorithmic traps discovered in real pull requests
1. Nested Loops for Lookups O(n²) → O(n)

Searching for matches by iterating through list B for each item in list A.

Fix: Index list B into a Hash Map or Set before iterating list A for O(1) lookups.
2. String Concatenation in Loops O(n²) Memory Copies

Using str += newChunk inside large loops copies the entire buffer on every tick.

Fix: Use StringBuilder, strings.Builder, or push into an array & call .join('').
3. Redundant Sorting O(n log n) → O(n)

Sorting an entire dataset just to extract the single maximum, minimum, or median item.

Fix: Use a single-pass linear scan for min/max, or a min/max heap for top-K elements.
4. Unmemoized Recursion O(2ⁿ) → O(n)

Recursive branch trees solving identical subproblems repeatedly (e.g. naive Fibonacci).

Fix: Cache solved subproblems in an array or map, or rewrite bottom-up iteratively.
